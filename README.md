# Помрок

Темрява прихопила світанок, а громада з Чорногори взялася його повертати. У лісі чекають упир-дзвонар, мавка-митарка й пан Помрок із брамою та трьома печатками. На сільському майдані можна битися з ботами або викликати на двобій іншого гравця.

«Помрок» — гра для Telegram на TypeScript і Fastify. У браузері є майданчик Next.js для тренувань. Обидва використовують спільні пригоди, правила й літопис бою українською.

## Запуск через Docker

1. Скопіюй `.env.example` у `.env`. Для Telegram задай `POMROK_BOT_KEY` токеном від [BotFather](https://t.me/BotFather).
2. Виконай `docker compose up --build -d`. Щоб запустити лише Telegram-бота, виконай `docker compose up --build -d api`.
3. Напиши боту `/start` в особистому чаті або відкрий [майданчик у браузері](http://localhost:3000). Якщо порт 3000 зайнятий, задай `WEB_PORT` у `.env`.

Без токена працюють браузерні тренування. Для довгого опитування також можна використовувати стару локальну змінну `TELEGRAM_BOT_TOKEN`. Якщо бот раніше працював через вебхук, вимкни його перед запуском довгого опитування.

### Локальний вебхук через ngrok

Задай у локальному `.env` токен Помроку `POMROK_BOT_KEY` і токен агента `NGROK_AUTHTOKEN`. Для `TELEGRAM_WEBHOOK_SECRET` створи випадкове значення командою `node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"`.

```powershell
docker compose -f compose.yaml -f compose.webhook.yaml up --build --wait --wait-timeout 90 api ngrok
```

ngrok передає запити на окремий порт контейнера, де доступний лише вебхук із секретною перевіркою. Помрок читає активну HTTPS-адресу з внутрішнього API ngrok і оновлює власний вебхук, якщо адреса змінюється. Контейнери відновлюють роботу після запуску Docker Desktop. Telegram відкриває меню команд зі свого інтерфейсу, а `/menu` показує кнопки пригод.

| Команда | Дія |
| --- | --- |
| `/start` | Зайти до корчми й відкрити меню |
| `/menu` | Відкрити меню пригод |
| `/story` | Дізнатися, куди подівся світанок |
| `/hero` | Обрати Щитника, Легіня або Мольфара |
| `/dungeon` | Обрати лісову пригоду |
| `/arena` | Битися з ботом або дізнатися, як викликати гравця |
| `/challenge @username` | Викликати іншого гравця |
| `/profile` | Переглянути рахунок і останній бій |
| `/help` | Прочитати правила бою |

Обидва гравці мають спочатку відкрити бота. Запрошений гравець має 24 години, щоб прийняти або відхилити виклик. Після згоди бот проводить бій і надсилає підсумок обом учасникам.

## GitHub Actions

На вкладці **Actions** запусти **Telegram bot** з гілки `main`. Робочий процес використовує секрет репозиторію `POMROK_BOT_KEY`, перевіряє ім’я бота та відсутність вебхука. Перевірка не запускає ще один процес опитування і не надсилає повідомлень.

Для постійної роботи бота потрібна машина з Docker, доступна через SSH. Використовуй її IP-адресу, якщо домену немає, і задай у GitHub такі параметри.

| Параметр | Де зберігати | Значення |
| --- | --- | --- |
| `POMROK_DEPLOY_HOST` | Actions variable | IP-адреса або ім’я машини |
| `POMROK_DEPLOY_USER` | Actions variable | SSH-користувач із доступом до Docker |
| `POMROK_DEPLOY_KNOWN_HOSTS` | Actions variable | Запис `known_hosts` із перевіреним ключем SSH-сервера |
| `POMROK_DEPLOY_SSH_KEY` | Actions secret | Приватний ключ SSH для розгортання |

Під час запуску робочого процесу встанови `deploy` у `true`. GitHub Actions передасть секрет бота середовищу контейнера й запустить лише сервіс `api`. Docker продовжить його роботу після завершення завдання. Розгортання пройде перевірку готовності після першої успішної відповіді на опитування Telegram. Використовуй лише один процес опитування для одного токена.

## Бої та збереження

Швидший боєць ходить першим. У скриньці по одній кульці з числами від 1 до 6. Витягнуті кульки повертають після спорожніння скриньки. Одиниця означає промах, шістка — критичний удар. Перше поранення до половини здоров’я або нижче може спричинити кровотечу чи слабкість. Після 24 раундів без переможця оголошується нічия.

Пролог, герої, зустрічі та їхні кінцівки зберігаються у `config/world.toml`. Рахунок гравців, виклики, літописи й черга повідомлень зберігаються в `state.toml` у томі Docker `game-data`. Зберігай том під час оновлень контейнера.

## Моніторинг

Задай у `.env` пароль `GRAFANA_ADMIN_PASSWORD` і запусти повний стек із додатковим Compose-файлом.

```powershell
docker compose -f compose.yaml -f compose.monitoring.yaml up --build -d
```

Відкрий [Grafana](http://localhost:3100/d/pomrok-uptime) і увійди як `admin` зі своїм паролем. Сторінка стає доступною після першого запуску Grafana, а графіки заповнюються після кількох зборів метрик. Для вебхука додай `-f compose.webhook.yaml` до тієї самої команди. Grafana доступна через локальний інтерфейс, а Prometheus, Blackbox Exporter і порти метрик — у мережі Docker. Історія Prometheus зберігається 45 днів у томі `prometheus-data`.

Оновлюй стек моніторингу тією самою командою Compose. Ручне розгортання з GitHub Actions використовує базовий Compose-файл і при оновленні конфігурації API прибирає налаштування експортера з додаткового файлу.

- **Доступність.** Blackbox Exporter перевіряє відповідь ігрового API, наявність арени на вебсторінці й готовність налаштованого бота. `bot_readiness` показує стан опитування в режимі polling і готовність реєстрації в режимі webhook. Доставку відповідей видно на графіках Telegram. Вікна 24 год, 7 і 30 днів показують частку успішних перевірок серед зібраних даних. Для вимірювання простою всього хоста запусти Prometheus і Blackbox Exporter на іншому хості та додай публічну HTTPS-адресу. Використай завдання `pomrok-probes-public` за зразком `pomrok-probes`, модуль `web_arena` і мітку `location: external`.
- **Гравці.** Нові й активні гравці рахуються за останні 24 год і 7 днів. Нові профілі рахуються від першого успішного збереження, активні — від останньої команди або натискання кнопки. Для старих профілів активність з’явиться після першої дії з новою версією. Завершені вебтренування відображаються окремо.
- **Запити.** Графіки показують обсяг, частку HTTP 5xx і p95 для вебсайту, ігрового API та вебхука. Для Telegram також доступні результати обробки оновлень, помилки Bot API, глибина черги й час доставки відповідей. Для вже накопичених повідомлень без часової позначки вік черги відраховується від запуску сервера.
- **Сповіщення.** Grafana оцінює правила для недоступності сервісів і метрик, відповідей у черзі понад дві хвилини та повторних помилок запису стану за п’ять хвилин. Для доставки сповіщень задай отримувача в **Alerting → Contact points** і підключи його в **Notification policies**.

## Розробка

Встанови Node.js 24 і виконай `npm ci`. Запускай `npm run dev:api` та `npm run dev` в окремих терміналах. Типові порти API й браузерного майданчика — 3001 і 3000.

| Команда | Дія |
| --- | --- |
| `npm run lint` | ESLint для TypeScript, Next.js і React Hooks |
| `npm run check` | Перевірка типів |
| `npm test` | Vitest |
| `npm run test:coverage` | Покриття V8 та звіт `coverage/lcov.info` |
| `npm run build` | Збірка Next.js |

Для SonarQube створи проєкт із ключем `pomrok`, задай `SONAR_HOST_URL` і `SONAR_TOKEN` та виконай `npm run test:coverage` і `npm run sonar`. Щоб увімкнути перевірку SonarQube після змін у `main`, задай змінну репозиторію `SONAR_HOST_URL` і секрет `SONAR_TOKEN`.
